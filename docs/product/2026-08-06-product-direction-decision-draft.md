## 0. 이 문서를 사용하는 방법

이 문서는 모든 내용을 확정안처럼 적지 않고 다음 네 상태로 구분한다.

- **확정에 가까움**: 지금까지 대화에서 방향에 동의한 내용
- **권장안**: 현재 조건에서 가장 현실적이라고 판단한 안
- **미정**: 출시 전에 사용자가 직접 선택해야 하는 내용
- **보류**: 서비스가 정착하거나 데이터가 쌓인 뒤 결정할 내용

문서 하단의 `결정 체크리스트`에서 항목을 선택한 뒤, 선택 결과를 본문에 반영하면 이 문서를 실제 제품 방향서로 승격할 수 있다.

## 1. 한 문장 방향

> MOEMOA는 사용자가 애니를 보며 남기고 싶은 장면·감정·짧은 감상문을 이미지 기반 Memory Card로 만들고, 이를 개인 아카이브와 보드에 수집해 다시 보거나 다른 사람과 공유하는 서비스다.

`포토카드`는 물리 상품이나 K-pop 수집품으로 오해될 수 있으므로 문서에서는 작업 명칭으로 `Memory Card`를 사용한다. 실제 제품 용어는 `Memory Card`, `Moment Card`, 별도 브랜드 용어 중에서 추후 결정한다.

핵심 경험은 다음과 같다.

```text
작품 찾기 또는 직접 입력
  → 장면 이미지·짧은 감상·감정으로 Memory Card 제작
  → 개인 Archive에 수집
  → 원하는 Board에 임의 분류
  → 시간이 지난 뒤 다시 발견
  → 권리와 공개 범위가 준비된 카드는 다른 사용자와 공유
```

## 2. 지금까지 합의된 방향

### 2.1 제품 정체성 — 확정에 가까움

- 작품 정보, 평점 순위, 커뮤니티 활동이 중심인 대형 애니 트래커와 직접 경쟁하지 않는다.
- 핵심은 `무엇을 봤는가`뿐 아니라 `그 작품을 봤을 때 어땠는가`를 빠르게 기록하는 것이다.
- 작품 하나에 카드 하나만 두지 않고, 같은 작품에서도 기억하고 싶은 장면과 시기마다 여러 Memory Card를 만들 수 있다.
- 작품 데이터는 카드 제작을 돕는 보조 인덱스이며, 제품의 주인공은 사용자가 만든 카드다.
- 긴 전문 리뷰보다 짧은 메모, 감정, 개인적 의미와 다시 보고 싶은 이유를 쉽게 남기게 한다.
- 공개 경쟁과 팔로워 수보다 개인 아카이브의 소유감, 수집감, 정리 만족도를 우선한다.
- 카드를 주제별로 묶는 Board는 단순 폴더가 아니라 사용자가 자기 기준으로 애니 경험을 재해석하는 핵심 구조다.
- 기록을 다시 보여주는 회고, 재발견, Board와 티어가 핵심 재방문 장치다.
- 공개 공유와 다른 사용자의 카드 저장은 개인 카드 경험이 검증된 뒤 단계적으로 연다.

### 2.2 초기 시장 — 확정에 가까움

- 초기 서비스 언어는 영어를 우선한다.
- 1차 사용자 확보 시장은 필리핀으로 둔다.
- 싱가포르는 영어 UX와 다른 소비 성향을 교차 검증하는 시장으로 활용한다.
- 베트남과 태국은 영어 베타의 활성화·재방문이 확인된 뒤 현지화를 검토한다.
- 처음부터 네 국가를 동시에 현지화하고 운영하지 않는다.

### 2.3 수익화 원칙 — 확정에 가까움

- 초기 목표는 수익 극대화보다 실제 사용자를 확보하고 기록 습관이 생기는지 확인하는 것이다.
- 베타에서는 핵심 기록 기능을 무료로 제공하고 서비스 내부 광고를 넣지 않는다.
- 프리미엄 기능은 서비스가 정착하고 충분한 사용자 데이터와 반복 사용 패턴이 생긴 뒤 검토한다.
- 장기적으로도 기본 기록, 기본 라이브러리, 데이터 내보내기와 삭제 기능은 무료로 유지한다.
- 광고는 기록 입력을 방해하지 않는 독자적 회고·통계·에디토리얼 화면에서 제한적으로 검토한다.
- 크리에이터 협업과 경품 캠페인은 현재 출시 범위에서 제외한다.

### 2.4 데이터·이미지 방향 — 새롭게 정리된 권장안

- AniList나 애니라이프에 계속 의존하는 구조에서 벗어나 자체 작품 카탈로그를 운영한다.
- 다만 외부 데이터를 복제해 자체 서버에 두는 것을 `자체 데이터`로 간주하지 않는다.
- 공식 출처와 재사용 가능한 공개 데이터를 바탕으로 사실 정보를 직접 검수·정규화한다.
- 매 분기 신작을 후보 수집 후 수동 승인하는 편집 운영 방식을 사용한다.
- 작품 메타데이터와 표지 이미지를 서로 다른 권리 문제로 취급한다.
- 이미지가 없어도 제품이 완성되어 보이는 디자인을 기본 전제로 한다.
- 사용자가 업로드한 이미지도 자동으로 공개 사용 권리가 생기는 것은 아니므로 이미지 출처·유형·공개 범위를 함께 기록한다.
- 비공개 개인 이미지와 공개 UGC 이미지를 별도 정책·저장 경로로 취급한다.

### 2.5 카드·보드·공유 방향 — 새롭게 정리된 권장안

- `Memory Card`를 감상 로그의 시각적 표현이 아니라 독립된 핵심 콘텐츠 단위로 둔다.
- `Archive`는 사용자가 만든 모든 카드를 시간·작품·감정별로 다시 보는 개인 공간이다.
- `Board`는 카드들을 `2026년 최고의 장면`, `새벽에 보기 좋은 애니`, `마음이 편해지는 작품`처럼 사용자가 임의로 분류하는 컬렉션이다.
- 하나의 카드는 여러 Board에 들어갈 수 있고, Board 안에서는 사용자가 순서를 직접 정할 수 있다.
- 다른 사용자의 카드를 저장할 때는 이미지를 복제하지 않고 원본 카드 참조와 작성자·출처를 유지한다.
- 공개 피드·추천·팔로우보다 `개인 카드 제작 → 개인 Board 구성 → 제한적 공유` 순서로 검증한다.

## 3. 제품 가치와 차별점

### 3.1 사용자에게 주는 핵심 가치

1. **순간 기록의 편의성**
   감상 직후 장면과 짧은 문장만으로 부담 없이 남길 수 있다.

2. **개인적인 맥락**
   객관적 작품 평가가 아니라 당시의 감정과 경험을 보존한다.

3. **수집하는 즐거움**
   카드가 쌓여 나만의 시각적 애니 아카이브가 된다.

4. **재발견**
   과거 기록, 특정 시기의 감정, 다시 보고 싶은 작품을 다시 꺼내준다.

5. **기록 소유권**
   사용자가 기록을 내보내고 복원하고 삭제할 수 있다.

6. **자기 기준의 재분류**
   장르나 평점이 아닌 감정·시기·장면·주제에 따라 Board를 만들 수 있다.

7. **공유 가능한 자기 표현**
   권리와 공개 범위가 준비된 카드를 다른 사용자 및 외부 SNS와 공유할 수 있다.

### 3.2 기존 트래커와의 구분

| 기존 트래커의 중심 | MOEMOA의 중심 |
| --- | --- |
| 작품 데이터와 검색량 | 개인의 감상 기억 |
| 점수와 순위 | 감정과 개인적 의미 |
| 작품당 하나의 목록 상태 | 한 작품에서 만들어지는 여러 장면·기억 카드 |
| 고정 장르와 분류 | 사용자가 만든 자유로운 Board |
| 공개 목록과 커뮤니티 | 개인 Archive에서 시작하는 선택적 공유 |
| 최신 정보 소비 | 기록의 축적과 재발견 |
| 공식 포스터 중심 작품 카드 | 사용자 경험 중심 Memory Card |

### 3.3 피해야 할 방향

- AniList를 축소 복제한 듯한 작품 상세 페이지
- 포스터와 줄거리 양으로 경쟁하는 데이터베이스
- 처음부터 소셜 피드와 팔로우 경쟁을 전면에 두는 구조
- 타인의 팬아트와 애니 장면 캡처를 무조건 공개할 수 있다고 전제하는 구조
- 리뷰를 길게 써야 카드가 완성되는 구조
- 작품을 찾지 못하면 아무것도 기록할 수 없는 구조
- Board를 단순 폴더로만 취급해 카드 재발견과 공유 맥락을 잃는 구조

## 4. 권장 핵심 사용자 흐름

### 4.1 첫 사용자

```text
빈 라이브러리
  → 작품 검색
  → 검색되지 않으면 직접 작품 생성
  → 장면 이미지 또는 기본 디자인 선택
  → 첫 Memory Card 작성
  → 카드가 Archive에 추가됨
  → 첫 Board 생성 또는 다음 카드 기록 안내
```

신규 사용자에게 가짜 작품이나 데모 기록을 실제 데이터처럼 넣지 않는다. 예시는 제품 설명 영역에서만 보여준다.

### 4.2 Memory Card

출시 시 필수 후보:

- 작품 제목
- 사용자 이미지 또는 서비스 기본 카드 디자인
- 짧은 감상문
- 감상 날짜
- 스포일러 표시
- 공개 범위: `Private`를 기본값으로 사용
- 이미지 유형과 출처

후속 후보:

- 감정 태그
- 에피소드·장면 정보
- 함께 본 사람·장소·시기
- 개인 점수 또는 만족도
- 다시 보고 싶은지 여부
- 재감상 기록
- 시즌별·연도별 회고 연결

이미지 없이도 기본 디자인 카드로 저장할 수 있어야 하고, 이미지가 있다고 해서 긴 글을 요구하지 않는다. `점수`, `감정 태그`, `감상 상태`를 모두 필수로 만들지 않으며 빠른 기록과 풍부한 기록 사이의 균형은 실제 베타에서 검증한다.

### 4.3 Archive와 재방문

- 최근 기록한 카드
- 기록 후 일정 시간이 지난 카드
- 같은 작품에서 서로 다른 시기에 만든 카드
- 다시 보고 싶다고 표시한 작품
- 같은 시기 또는 같은 감정으로 묶인 기록
- 연간·분기별 감상 회고
- Board와 티어

### 4.4 Board와 공유

- Board는 제목·설명·공개 범위·카드 순서를 가진다.
- 하나의 Memory Card를 여러 Board에 배치할 수 있다.
- 다른 사용자의 공개 카드를 내 Board에 저장할 때는 원본 카드 ID를 참조하고 작성자와 출처를 유지한다.
- 원본 카드가 삭제되거나 비공개로 전환되면 다른 사용자의 Board에서도 접근이 중단되어야 한다.
- 공개 공유 전에는 스포일러, 이미지 권리, 성인·유해 콘텐츠 상태를 확인한다.

권장 데이터 관계:

```text
Anime 1 ─ N MemoryCard
MemoryCard N ─ M Board  // BoardCard로 순서와 저장 시각 관리
MemoryCard 1 ─ 0..1 ImageAsset
MemoryCard N ─ 0..N SavedReference
```

## 5. 자체 작품 카탈로그 전략

### 5.1 기본 원칙

자체 카탈로그를 가진다는 것은 다음을 직접 소유·운영한다는 뜻이다.

- 자체 내부 작품 ID
- 데이터 구조와 정규화 규칙
- 작품 중복 판별 규칙
- 출처 및 검증 이력
- 자체 작성한 검색 별칭
- 수정 기록과 분기별 편집 과정

외부 사이트에서 가져온 데이터의 권리가 서버에 복사했다는 이유로 서비스 소유가 되는 것은 아니다.

AniList는 API의 백업·저장 용도와 대량 수집을 금지하고, 애니·만화 목록 및 트래커 성격의 서비스를 별도 제한 대상으로 둔다. 따라서 향후 카탈로그의 주 데이터 원천으로 계속 사용하지 않는 것이 권장된다.

- [AniList API Terms of Use](https://docs.anilist.co/guide/terms-of-use)
- [대한민국 저작권법 제93조: 데이터베이스제작자의 권리](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025203419)

### 5.2 현재 보유 데이터의 위치

현재 `src/data/aliases.json`에는 3,998개 레코드가 있으며 구조는 다음 세 필드다.

```text
anilistId
ko
aliases
```

이 데이터에는 작품의 연도·분기·형식·출처·검증 상태가 없다. AniList와 애니라이프에서 수집했던 이력도 있으므로 다음처럼 취급하는 것이 권장된다.

- 즉시 삭제하지 않는다.
- `legacy_unverified`로 분류한다.
- 내부 검색 후보, 제목 매칭, 중복 탐지의 참고 자료로만 사용한다.
- 출처를 새로 확인하기 전에는 정식 공개 카탈로그 데이터로 간주하지 않는다.
- 최근 작품과 실제 검색이 많은 작품부터 점진적으로 깨끗한 출처로 교체한다.

### 5.3 정식 카탈로그의 권장 필드

```text
id                   // 서비스 내부 ID
nativeTitle          // 원제
englishTitle         // 공식 영문 제목이 확인된 경우
localizedTitles      // 국가별 공식 유통 제목과 출처
searchAliases        // 자체 검수한 검색 별칭
releaseYear
season
format
startDate
endDate
episodeCount
studioNames
officialSiteUrl
status
createdAt
updatedAt
```

출처·권리 필드:

```text
sourceName
sourceUrl
sourceType           // official, open-data, legacy, user
license
retrievedAt
verifiedAt
verifiedBy
rightsStatus         // verified, pending, legacy_unverified
fieldProvenance      // 필드별 출처가 다를 때 사용
```

### 5.4 출처 우선순위

1. 작품 공식 홈페이지
2. 제작사·방송사·정식 배급사 페이지
3. 공식 스트리밍 사업자의 작품 정보
4. 재사용 조건이 명확한 공개 데이터 — 예: Wikidata의 구조화 데이터
5. 사용자 수정 제보 — 출처 확인 후 승인
6. 기존 AniList·애니라이프 데이터 — 발견과 대조용으로만 사용

공식 페이지의 사실을 확인하는 것과 그 페이지의 소개문·이미지를 복사하는 것은 구분한다. 줄거리와 설명문은 직접 작성하거나 초기에는 제공하지 않는다.

### 5.5 초기 카탈로그 범위 — 권장안

처음부터 모든 역사적 작품을 정식 검수할 필요는 없다.

- 다가오는 분기 신작
- 최근 2~3년의 주요 작품
- 기존 사용자 데이터에서 실제 사용 빈도가 높은 작품
- 검색되지 않는 과거 작품은 사용자가 개인 전용 카드로 직접 생성
- 직접 생성된 작품이 반복적으로 요청될 때 공용 카탈로그 승격 검토

이 방식은 출시를 늦추지 않으면서 롱테일 작품도 기록할 수 있게 한다.

### 5.6 분기별 편집 운영

| 시점 | 작업 |
| --- | --- |
| 방영 1~2개월 전 | 공식 발표를 바탕으로 신작 후보 등록 |
| 방영 직전 | 제목, 형식, 제작사, 시작일 검증 |
| 방영 2~4주 후 | 연기, 분할 방영, 화수 변경 수정 |
| 종영 후 | 최종 화수와 완결 상태 확정 |

운영 도구는 `자동 후보 수집 → 관리자 검토 → 승인 → 변경 이력 저장` 형태를 권장한다. 처음에는 관리자 화면과 CSV 가져오기만으로도 충분하다.

## 6. 이미지 정책

### 6.1 공통 원칙

- 포스터·키아트·캐릭터 이미지는 작품 사실 정보와 별도의 저작물로 취급한다.
- 이미지 URL을 알고 있거나 사용자가 업로드했다는 이유만으로 상업적 표시 권리가 확보되는 것은 아니다.
- 사용자가 직접 캡처한 애니 장면과 타인이 만든 2차 창작 이미지도 원저작물 또는 창작자의 권리가 존재할 수 있다.
- 인터넷 이미지 URL을 그대로 연결하는 hotlink 방식은 권리 문제를 해결하지 않으며 링크 만료, 차단, 추적과 성능 문제도 만든다.
- 공개 공유 카드와 유료 광고 소재에는 권리가 확인되지 않은 이미지를 사용하지 않는다.
- 전역 설정으로 외부 이미지를 즉시 숨길 수 있어야 한다.
- `Private`, `Unlisted`, `Public`은 단순 UI 설정이 아니라 서로 다른 권리·신고·노출 정책으로 운영한다.

### 6.2 이미지 유형별 초기 공개 정책

| 이미지 유형 | Private | Public | 초기 원칙 |
| --- | --- | --- | --- |
| 서비스 기본 디자인 카드 | 허용 | 허용 | **출시 기본값** |
| 사용자 기기에만 저장한 이미지 | 허용 | 해당 없음 | 초기 개인 카드의 주 이미지 방식 |
| 사용자가 직접 만든 원본 이미지·그림 | 허용 | 권리 확인 동의 후 후보 | 공개 UGC 1차 허용 범위 |
| 사용자가 직접 만든 2차 창작 | 허용 | 원저작물·적용 법률 검토 후 제한적 후보 | 무조건 허용하지 않음 |
| 사용자가 캡처한 애니 장면 | 허용 후보 | 초기 비허용 권장 | 공개 사용을 일반적 예외로 가정하지 않음 |
| 다른 작가의 팬아트 재업로드 | 개인 사용도 주의 | 허가 없이는 비허용 | 출처 표기만으로 허가를 대신하지 못함 |
| CC·공개 라이선스 이미지 | 조건에 따라 허용 | 라이선스·출처 기록 후 허용 | 조건 자동 표시 필요 |
| 정식 공급자 이미지 | 계약 범위에 따라 허용 | 계약 범위에 따라 허용 | 장기 조사 |
| 인터넷 이미지 URL hotlink | 권장하지 않음 | 권장하지 않음 | 권리·안정성 문제를 해결하지 못함 |

### 6.3 공개 UGC를 위한 플랫폼 요건

Pinterest도 사용자가 올렸다는 이유만으로 이미지를 무조건 허용하지 않는다. 게시 권리가 있는 콘텐츠만 올리도록 요구하고, 서비스 표시·저장·배포에 필요한 라이선스를 받으며, 저작권 신고·삭제·이의제기·반복 침해자 제재 체계를 운영한다.

- [Pinterest 서비스 약관 — 사용자 콘텐츠](https://policy.pinterest.com/ko/terms-of-service)
- [Pinterest 저작권 정책](https://policy.pinterest.com/en/copyright)
- [대한민국 저작권법 제102조 — 온라인서비스제공자의 책임 제한](https://www.law.go.kr/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1025203239)

온라인서비스제공자 책임 제한은 요건을 충족했을 때 책임을 제한하는 장치이지, 이미지 이용 허가를 새로 만들어주는 제도가 아니다. 공개 이미지 공유를 열기 전 최소한 다음이 필요하다.

- 사용자가 게시 권한이 있음을 확인하는 업로드 동의
- 이미지 유형·원작자·출처 URL·라이선스 기록
- 권리자 신고와 신속한 접근 차단·삭제
- 업로더 통지와 이의제기·복구 절차
- 반복 침해자 경고·제한·계정 중단 정책
- 스포일러, 성인물, 폭력적 이미지 신고와 노출 제한
- 원본·리사이즈 파일의 일괄 삭제 경로
- 대상 국가별 약관·저작권·플랫폼 규제 검토

### 6.4 권장 출시안

1. 제목·색상·타이포그래피·간단한 패턴으로 서비스 기본 커버를 생성한다.
2. 개인 Memory Card는 사용자가 자기 기기에만 이미지를 지정할 수 있게 한다.
3. Private Board와 Archive의 사용성을 먼저 검증한다.
4. 서버 업로드는 이용약관, 저작권 신고, 삭제 처리, 용량 제한이 준비된 뒤 비공개 범위로 시험한다.
5. 공개 공유 카드는 이미지가 없어도 텍스트·도형 중심으로 완성되게 한다.
6. 첫 공개 이미지 범위는 사용자 원본 또는 라이선스가 명확한 이미지로 제한한다.
7. 다른 사용자의 카드를 Board에 저장할 때는 파일을 재복제하지 않고 원본 카드 참조를 유지한다.
8. 애니 장면 캡처의 공개 공유와 타인 팬아트 재업로드는 별도 법률·운영 판단 전까지 열지 않는다.
9. 정식 이미지 사용 허가를 확보하면 공급자별로 기능을 켤 수 있게 한다.

## 8. 동남아 출시 계획

### 8.1 출시 순서 — 권장안

```text
내부 알파
  → 영어 개인 Memory Card·Private Board 베타
  → 권리가 명확한 콘텐츠의 제한적 공유 베타
  → 필리핀 중심 유료 유입 실험
  → 싱가포르 교차 검증
  → 제품 수정
  → 베트남 또는 태국 한 국가씩 현지화 검증
```

### 8.2 출시 전 조건

- 작품 데이터가 외부 API 실패 없이 기본 검색과 기록을 지원한다.
- 외부 이미지가 모두 꺼져도 제품이 정상적으로 보인다.
- 데이터 출처와 검증 상태를 추적할 수 있다.
- 모바일에서 첫 작품 추가와 첫 로그 저장이 안정적이다.
- 모바일에서 첫 Memory Card를 짧은 시간 안에 완성할 수 있다.
- 동기화가 없는 상태를 클라우드 저장 완료처럼 표시하지 않는다.
- 사용자가 자신의 데이터를 내보내고 삭제할 수 있다.
- 공개 연락처와 저작권 삭제 요청 절차가 있다.
- 공개 공유를 연 경우 신고·차단·이의제기·반복 침해자 절차가 동작한다.
- 다른 사용자의 카드 저장은 원본 참조와 작성자·출처를 유지한다.
- 광고 소재가 제3자 포스터나 캐릭터 이미지에 의존하지 않는다.

### 8.3 초기 메시지 후보

- `Your anime memories, not just a score.`
- `Remember why an anime mattered to you.`
- `A quiet personal anime journal.`
- `Turn every anime you watch into a memory card.`
- `Save the anime moments you don't want to forget.`
- `Build boards from the scenes and feelings you remember.`

Memory Card·Board 중심 문구는 개인 기록 메시지와 별도로 비교한다. 공개 UGC 이미지가 준비되기 전 광고 소재에는 사용자가 올린 애니 장면이나 팬아트를 사용하지 않는다.

## 9. 초기 홍보 계획

### 9.1 채널

- 초기 유료 실험은 Instagram과 Facebook을 포함한 Meta 광고를 우선 검토한다.
- TikTok은 제품을 실제로 사용하는 짧은 영상의 유기적 반응을 먼저 본다.
- 유료 광고 비용은 집행 직전 최신 국가별 CPM·CPC·전환 추정치를 다시 조사한다.
- 설치나 클릭이 아니라 `첫 Memory Card 저장`에 가까운 이벤트를 캠페인 최적화 목표로 삼는다.
- 공개 공유가 준비되면 사용자가 직접 외부 SNS로 공유한 카드와 Board를 유기적 유입 루프로 측정한다.

### 9.2 광고 소재 원칙

- 애니 포스터, 캐릭터, 장면 캡처를 사용하지 않는다.
- 실제 제품 UI, 카드가 쌓이는 모습, 타이포그래피와 색상을 사용한다.
- `평점을 기록하세요`보다 `그때의 감정을 남겨두세요`를 강조한다.
- 한 작품에서 여러 Memory Card가 쌓이고 Board로 묶이는 과정을 시각적으로 보여준다.
- 국가별로 같은 소재와 메시지를 먼저 비교한 뒤 현지화한다.
- 클릭률이 아니라 활성화 사용자당 비용과 7일 재방문을 기준으로 판단한다.

### 9.3 기존 예산 가안 — 아직 미정

이전에 논의한 4주 600,000원 가안은 다음과 같다.

- 필리핀: 420,000원
- 싱가포르: 120,000원
- 성과 재배분 예비비: 60,000원

이 금액은 수익 회수 예산이 아니라 시장·메시지 학습 예산이다. 실제 집행 전 광고 단가를 다시 확인하고, 제품의 첫 카드 저장 흐름이 준비되지 않았다면 집행하지 않는다.

| --- | --- |
| 준비 | 분석 이벤트, 랜딩, 법적 페이지, 광고 소재, 권리 안전 상태 점검 |
| 1주차 | 국가·메시지별 첫 반응 비교 |
| 2주차 | 첫 Memory Card 저장 퍼널과 소재 개선 |
| 3주차 | D7 재방문, 두 번째 카드, 첫 Board 생성 여부 관찰 |
| 4주차 | 필리핀 집중, 제품 수정, 다음 국가 검증 중 하나 선택 |

## 10. 수익화 방향

### 10.1 단계별 원칙

```text
무료·무광고 베타
  → 사용 습관과 권리 구조 확인
  → 독자적 회고·통계 화면의 제한적 광고
  → 충분한 사용 데이터가 쌓인 뒤 선택형 서포터 기능 검토
```

### 10.2 광고를 넣지 않을 위치

- 감상 카드 작성 중
- 저장 직후 전면 팝업
- 작품 검색 결과의 카드 사이
- 작품 선택 모달
- 로그인, 백업, 복원, 동기화 충돌 해결
- 계정·데이터 삭제 화면

### 10.3 광고 후보 위치

- 연간·분기 회고의 섹션 사이 또는 하단
- 사용자가 작성한 기록을 집계한 긴 통계 화면 하단
- 서비스가 직접 작성한 시즌 회고·에디토리얼
- 독자적 설명이 충분한 공개 Board 하단

### 10.4 프리미엄 — 보류

사용자가 돈을 낼 만한 기능을 지금 억지로 만들지 않는다. 향후 실제 사용 패턴을 본 뒤 다음 후보를 검토한다.

- 광고 제거
- 추가 테마와 카드 디자인
- 고급 회고 레이아웃
- 추가 공유 카드 스타일
- 추가 Board 테마와 레이아웃
- 비공개 이미지의 추가 저장 용량
- 장기 기록 기반의 개인 분석

구독보다 일회성 `Supporter Pack`이 먼저 검증하기 쉬운 후보지만 아직 확정하지 않는다.

## 13. 기능 개발 로드맵

### 단계 0 — 방향 확정

- 이 문서의 미정 항목 선택
- 공용 카탈로그 범위 확정
- 사용자 이미지 저장·공개·공유 범위 확정
- Memory Card와 Board의 출시 범위 확정
- 초기 출시 국가와 광고 예산 확정
- 서비스명과 핵심 메시지 확정

### 단계 1 — 데이터·이미지 기반 교체

- 내부 작품 ID와 출처 포함 카탈로그 스키마 설계
- 기존 3,998개 별칭 데이터를 `legacy_unverified`로 마이그레이션
- AniList 런타임 의존을 공급자 인터페이스 뒤로 격리
- 외부 이미지 전체 차단 모드 완성
- 기본 디자인 커버 구현
- 작품 직접 생성과 공용 작품의 구분 구현
- 분기별 작품 등록 관리자 화면 또는 CSV 도구 구현

### 단계 2 — Memory Card와 개인 Archive

- 첫 작품 추가와 첫 카드 작성 흐름 재설계
- 한 작품에 여러 Memory Card를 연결하는 데이터 구조 구현
- 카드 작성 필수·선택 필드 최소화
- 이미지 없는 기본 디자인 카드와 로컬 개인 이미지 구현
- 라이브러리를 개인 Archive로 재구성
- 최근 기록과 과거 기록 재발견 강화
- 모바일 기록 시간을 단축

### 단계 3 — Private Board

- `Board`, `BoardCard`, 카드 순서 데이터 구조 구현
- 하나의 카드를 여러 Board에 배치
- Board 생성·편집·삭제와 드래그 정렬
- 기존 티어를 Board 계열 기능으로 연결할지 검증
- Board 기반 재발견과 회고 구현

### 단계 4 — 제한적 공유와 공개 베타 안전 장치

- 데이터 내보내기·복원·삭제 검증
- 선택적 클라우드 동기화 검증
- 개인정보처리방침·이용약관·저작권 신고 페이지
- 이미지 출처·유형·라이선스·공개 범위 저장
- 권리가 명확한 이미지부터 `Unlisted / Public` 공유
- 스포일러 가림, 콘텐츠 신고, 접근 차단, 이의제기
- 다른 사용자의 카드를 파일 복제 없이 Board에 참조 저장
- 분석 이벤트와 오류 추적
- 영어 카피 전체 점검
- 외부 이미지 0건 모드 E2E 검증

### 단계 5 — 동남아 베타와 홍보

- 소규모 실제 사용자 테스트
- 필리핀 중심 4주 광고 실험
- 싱가포르 교차 검증
- 첫 카드 저장, 두 번째 카드, 첫 Board 생성 퍼널과 D7 리텐션 분석
- 결과에 따라 제품 수정 또는 다음 시장 선택

### 단계 6 — 소셜 확장·리텐션·수익화

- 연간·분기 회고 개선
- 사용자 기록 기반 재발견 강화
- 공개 카드·Board 탐색과 팔로우를 단계적으로 검토
- 창작자 직접 게시·관리 구조 검토
- 독자 콘텐츠 화면의 광고 적합성 검토
- 제한적 광고 A/B 테스트
- 데이터가 충분할 때만 서포터 기능 조사

## 14. 현재 프로젝트 상태 메모

- `master`에는 동남아 출시·수익화 설계, 단계별 구현 계획, 제품 안정화 작업이 모두 병합·push되어 있다.
- 신규 사용자 빈 상태, 영어 기본 UX, 퀵로그 원자적 저장, 저장·동기화·레거시 마이그레이션 안정화는 구현·검증 완료 상태다.
- 현재 런타임 검색·상세 정보·표지 이미지는 여전히 AniList 의존 구조다.
- 자체 카탈로그, `legacy_unverified` 마이그레이션, Memory Card·Archive·Board·제한적 공유 구조는 아직 구현 전이다.
- 기존 구현 계획은 폐기 대상이 아니라 새 방향의 기반 안정화 작업으로 유지한다.

## 15. 결정 체크리스트

아래 항목의 선택지를 표시하고 의견을 적으면 다음 문서 개정에서 확정안으로 반영할 수 있다.

### D-01. 공용 카탈로그 초기 범위

- [ ] **권장:** 다가오는 분기 + 최근 2~3년부터 시작하고 과거작은 점진 추가
- [ ] TV 애니 중심으로 범위를 더 좁힘
- [ ] 출시 전 기존 3,998개 전체를 검증

메모:

### D-02. 카탈로그에 없는 작품

- [ ] **권장:** 사용자가 개인 전용 작품을 즉시 만들 수 있음
- [ ] 관리자 등록 요청 후에만 기록 가능

메모:

### D-03. 기존 AniList·애니라이프 데이터

- [ ] **권장:** `legacy_unverified`로 보관하고 내부 매칭·검증 보조로만 사용
- [ ] 전부 제거하고 처음부터 재구축
- [ ] 다른 사용 범위를 법률 검토 후 결정

메모:

### D-04. 출시 시 작품 이미지

- [ ] **권장:** 서비스 기본 디자인 카드 + 선택적 사용자 기기 로컬 이미지
- [ ] 기본 디자인 커버만 사용
- [ ] 비공개 클라우드 업로드까지 출시 범위에 포함
- [ ] 정식 이미지 공급자를 확보할 때까지 출시 보류

메모:

### D-05. 사용자 이미지 공개 범위

- [ ] **권장:** 초기에는 모든 사용자 이미지가 Private이고, 공개는 본인 원본·허가·공개 라이선스 이미지부터 단계적으로 허용
- [ ] 공유 카드는 이미지 없이 텍스트·도형만 사용
- [ ] 사용자가 캡처한 애니 장면도 공개 공유 허용
- [ ] 타인 팬아트도 출처 표기 후 공개 허용

애니 장면 캡처와 타인 팬아트 공개는 별도 법률·운영 검토 전까지 권장하지 않는다.

메모:

### D-06. 계정 정책

- [ ] **권장:** 로그인 없이 로컬 사용 가능, 로그인하면 선택적 동기화
- [ ] 처음부터 계정 필수

메모:

### D-07. 초기 시장

- [ ] **권장:** 필리핀 주 시장 + 싱가포르 소규모 교차 검증
- [ ] 필리핀만 집중
- [ ] 영어권 동남아를 국가 구분 없이 운영

메모:

### D-08. 초기 광고 집행 예산

- [ ] **기존 가안:** 4주 최대 600,000원
- [ ] 더 작은 사전 실험 후 증액
- [ ] 무광고 유기적 베타로 먼저 검증

메모:

### D-09. 제품 내 광고 도입 시점

- [ ] **권장:** 두 개 이상의 코호트에서 리텐션 확인 후 제한 실험
- [ ] 월간 페이지뷰 기준을 먼저 정하고 도입
- [ ] 당분간 제품 내 광고도 보류

메모:

### D-10. 프리미엄

- [ ] **권장:** 충분한 데이터가 쌓일 때까지 구체 설계 보류
- [ ] 일회성 Supporter Pack을 초기부터 준비
- [ ] 구독 모델을 초기부터 준비

메모:

### D-11. 핵심 감상 카드 필드

- [ ] **권장:** 작품 제목만 필수, 이미지·짧은 감상·감정·날짜는 선택
- [ ] 작품 제목 + 이미지 또는 기본 디자인 + 짧은 감상을 필수
- [ ] 작품 제목 + 이미지 + 점수 + 감상 상태를 필수

추가하고 싶은 필드:

### D-12. 서비스명과 대표 문구

- [ ] 서비스명 `MOEMOA` 유지
- [ ] 서비스명 재검토
- [ ] 대표 문구 `Remember what you watched, and how it felt.` 유지
- [ ] Memory Card·Board 중심 문구로 변경

메모:

### D-13. 작품과 Memory Card의 관계

- [ ] 작품당 대표 카드 하나만 유지
- [ ] **권장:** 같은 작품에서도 장면·시기마다 여러 Memory Card 생성 가능

메모:

### D-14. Board의 초기 출시 범위

- [ ] **권장:** 개인 카드 베타부터 Private Board 포함
- [ ] 카드 Archive만 먼저 출시하고 Board는 P1에서 추가
- [ ] 처음부터 Public Board와 탐색까지 포함

메모:

### D-15. 다른 사용자의 카드 저장 방식

- [ ] **권장:** 원본 카드 참조만 내 Board에 저장하고 작성자·출처 유지
- [ ] 저장 시 카드와 이미지를 내 계정으로 복제
- [ ] 다른 사용자의 카드 저장 기능을 당분간 제공하지 않음

메모:

### D-16. 카드 기능 명칭

- [ ] **권장:** `Memory Card`
- [ ] `Moment Card`
- [ ] `Photo Card`
- [ ] 별도 브랜드 용어 제작
