# MOEMOA · 첫 정식 출시 실행 패키지 v2

작성일: 2026-09-22 (Asia/Seoul)  
상태: **수정된 출시 목표를 반영한 실행 지침. 구현·배포 완료 보고서가 아니다.**

## 이번에 고정하는 목표

**개인 기록 + 계정 기반 사용 + 공개 보드 + 공개 미니홈 + 팔로우 + 최소 운영·관리**를 첫 정식 출시의 한 묶음으로 완성한다.

사용자 A가 기억을 남기고 일부를 보드·미니홈에 공개한다. 비로그인 방문자가 선택된 내용만 보고, 사용자 B가 A를 팔로우해 나중에 다시 방문한다. A와 관리자는 공개를 철회할 수 있고, 운영자는 제한·신고 처리·갱신·복구를 수행할 수 있다.

Guest/Private-only는 중간 테스트 상태일 뿐, 이 목표의 완료 대안이 아니다. Public은 작업 중 안전한 격리 환경에서 개발하고, 최종 운영 활성화는 출시 승인 뒤에 한다.

## 파일은 네 개, 상시 갱신하는 진행판은 한 개

| 파일 | 읽는 때 | 역할 |
|---|---|---|
| `00_CODEX_START_HERE.md` | 처음 또는 세션 재개 | 작업 진입과 복사할 프롬프트 |
| `01_RELEASE_EXECUTION_PLAN.md` | 처음, 단계가 바뀔 때 | 고정된 6단계, 범위 통제, 변수 대응, 최종 종료 조건 |
| `02_ACCEPTANCE_CONTRACTS.md` | 현재 작업이 참조한 계약만 | 공개·이미지·UX·운영·검증 기준과 이전 지적 매핑 |
| `03_RELEASE_WORKBOARD.md` | 매 작업 시작·종료 | 현재 위치, 평면 작업 목록, 차단·결정·증거·다음 행동 |

`sources/SOURCE_BASELINE.json`은 출처와 무결성 정보다. 실행 순서 문서가 아니다. 체크섬도 작업이 아니라 전달 파일의 확인용이다.

**새 단계별 계획서·하위 계획서·보완 패키지를 계속 만들지 않는다.** 필요한 상세는 기존 작업의 체크리스트나 진행판 한 행에 넣는다. 테스트 코드·마이그레이션·실행 증거 파일은 만들 수 있지만 새 계획 트리가 되면 안 된다.

## 기존 문서와의 관계

제품 결정의 최상위 문서는 계속 `docs/moemoa/01_CONFIRMED_DECISIONS_AND_OPEN_GATES.md`다. 다만 사용자가 이번 대화에서 승인한 출시 범위를 M0에서 그 문서의 Decision Log에 반영한다. 기존 문서 전체를 덮어쓰지 않는다.

아래 항목만 기존 9월 22일 마감 문서의 전제를 교체한다.

- `Public 비활성으로 출시` → **공개 보드·미니홈·팔로우와 운영 게이트 완료 후 출시**.
- `Guest-only 또는 Account 포함 중 선택` → **계정과 Public은 첫 정식 출시 필수**.
- `moderation/공개 이미지 업로드는 이번 범위 밖` → **현재 최소 공개 기능을 안전하게 제공하는 범위만 필수**.
- `도움말에서 미니홈 안내 제거` → **구현·검증된 가용 상태와 안내를 일치**. 미검증 단계에서 미리 제공한다고 쓰지 않는다.
- `개인 이미지의 모든 클라우드 기능 제외` → **사용자가 공개하기로 선택한 이미지의 전달용 업로드만 추가**. 비공개 이미지 자동 백업은 여전히 범위 밖.

공식 표지의 승인된 VisualAsset 사용, 사용자 명시 선택, 개인 신호 조건, 작품 저장과 카드 생성의 독립성, Board N:M, 로컬 원본 보호는 유지한다. 친구 매칭·DM·댓글·추천 피드·새 전시물은 이번 계획에 추가하지 않는다.

## 저장소에 배치하는 방법

이 네 문서를 한 디렉터리(권장: `docs/moemoa/release-v2/`)에 둔다. 경로가 이미 있다면 기존 진행 내용과 비교해 갱신하며 초기 템플릿으로 덮어쓰지 않는다.

`CODEX_START_HERE.md`의 활성 작업 링크를 이번 `01`과 `03`으로 연결한다. 기존 `AGENTS.md`의 보안·승인 규칙은 삭제하지 않는다. `PLANS.md`가 요구하는 ExecPlan 항목은 `01`의 17개 절과 `03`의 진행 기록으로 충족한다. 같은 이유로 별도 ExecPlan을 매번 새로 만들 필요가 없다.

이번 대화의 출시 목표 승인은 운영 배포, 실 DB 변경, 유료 인프라 구매, 사용자 자료 삭제의 포괄적 실행 승인이 아니다.

## 완료 선언의 기준

문서를 읽었음, 화면이 존재함, mock에서 통과함, production build가 성공함은 각각 다른 상태다. **6단계 검증 + 필수 외부 결정 + 운영 활성 상태 확인**을 모두 충족해야 목표에 도달한다. `READY_FOR_DEPLOY`와 실제 `LIVE_VERIFIED`도 구분한다.

## 이 패키지에서 실제로 한 일

9월 22일 검토서, 최신 소스 ZIP의 진입 문서·AGENTS·PLANS, 이번 대화의 수정된 목표를 대조해 계획을 작성했다. 현재 작업 저장소의 코드를 수정·재실행하거나 운영을 재검증하지 않았다. 이전 감사의 재현 결과는 과거 근거이며 현재 코드에서 다시 확인한다. 일부 오래된 첨부의 만료 안내가 있었지만 이번 계획에 필요한 9월 22일 ZIP과 마감 문서는 접근 가능했다. 더 오래된 원본을 별도 비교할 경우에만 재첨부가 필요하다.
