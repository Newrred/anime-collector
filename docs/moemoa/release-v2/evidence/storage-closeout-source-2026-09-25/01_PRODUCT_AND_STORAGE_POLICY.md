# MOEMOA · 기록용 이미지와 무료/미래 상품 정책

2026-09-25 · 사용자 합의와 검증할 설정 후보를 분리한 문서. 현재 코드의 완성 선언이나 이용약관 원문이 아니다.

## 1. 첫 Web 출시의 약속

**같은 계정으로 휴대폰 웹에서 남긴 이미지·감상·Board를 PC 웹에서 다시 보고, 변경 결과를 다시 휴대폰에서 확인한다. 공개하지 않아도 된다.**

계정의 명시적인 비공개 연동 선택에 따라 기록용 사본을 저장한다. 비로그인 기록과 과거 기기 이미지 전체는 자동 업로드하지 않는다. 기존 Guest 승격 preview/확인 경로를 유지한다. 매번 불필요한 확인창을 추가하지 말고 새 이미지의 저장 행동에 저장 범위를 명확하게 표시한다.

첫 출시에서는 ‘원본 보관/원본 그대로 복원/무제한 백업/광고 없음 평생 보장’을 약속하지 않는다. 그래도 서버에 맡긴 **최적화 사본**에는 정상적인 보존·삭제·사본·복구 책임이 있다. 원본 백업 미제공이 서버 파일 유실을 방치할 이유는 아니다.

## 2. 세 가지 자료는 서로 다른 역할이다

| 자료 | 실제 의미 | 저장/접근 |
|---|---|---|
| 기기 원본 | 사용자가 선택한 캡처·사진의 원래 파일 | 사용자의 기기. 서버에 전부 올리지 않고 수정·삭제하지 않음 |
| 비공개 최적화 사본 | 기기 간 감상에 쓰는 큰 이미지+썸네일 | 소유자 인증·서버 권한 하에서만 읽기. 첫 출시의 추가 핵심 |
| 공개 사본 | 명시적으로 선택·검토·공개한 버전의 표현물 | 기존 공개 승인·철회·신고 정책. 비공개 버킷을 공개로 바꾸지 않음 |

카드의 감상/제목/날짜는 메타데이터다. 이미지 파일이 준비되지 않은 다른 기기에 메타데이터가 왔다고 ‘모두 연동됨’이라 표시하지 않는다.

**금지:** 비공개 이미지를 공개 보드에 올려야 PC에서 볼 수 있는 구조, 공개 URL을 사실상 개인 이미지 주소로 사용, 기존 카탈로그 표지로 누락된 개인 이미지를 조용히 대체.

## 3. 무료 상품 — 이번 구현 후보

| 항목 | 후보 | 변경 가능 범위 |
|---|---|---|
| 기본 기록/공개 보드/미니홈/팔로우 | 기존 출시 목표대로 무료 | 새 유료 잠금 없음 |
| 무료 개인 이미지 공간 | **50MB = 50,000,000bytes** | D03 측정·품질 확인 후 최종 활성값 기록 |
| 큰 최적화 사본 | **장당 최대1MB = 1,000,000bytes** | 1MB 원본 선택 제한이 아니라 보관 출력 상한 |
| 썸네일 | 최대120,000bytes, 긴 변400px 후보 | 새 제안. 실제 품질에 따라 조정 |
| 큰 사본의 긴 변 | 1,600px 시작값, 비율 유지·자동 확대 금지 | 실제 캡처의 자막/선/표정/암부를 보고 조정 |
| 입력 이미지 선택 | 기기에서 최대20MB·24MP 후보, JPEG/PNG/정적WebP | 새 제안. 기기 메모리 검증 전 보장하지 않음 |
| 전송 body | 최대1.5MB 후보 | 최적화 이후 bytes만 보내며 기존 provider 하한도 확인 |
| 동시 업로드 | 계정당1개 시작값 | 서버 우회·여러 탭 검증 |
| 일일 새 이미지 준비 | 10건 시작값 | 취소/재시도 작업과 정상 신규 작업을 구분 |
| 작은 파일 남용 방지 | managed asset 최대1,000개 후보 | 상품의 ‘1,000장 보장’ 아님. 50MB가 먼저 제한할 수 있음 |
| 월 비공개/공개 이미지 전송 | **미정: D03 측정 후 정함** | null을 무제한으로 구현하지 않음 |
| 무활동·용량 초과 자동삭제 | 첫 버전에서 하지 않음 | 휴면 정리 정책은 필요 시 사전 고지·별도 결정 |

수백 KB로 충분한 이미지를 1MB까지 키우지 않는다. 크기 약속과 화질 합격을 별개로 확인한다. ‘몇 장 저장 가능’은 실제 평균에 따라 달라지므로 확정 수량으로 광고하지 않는다.

**50MB는 현재 보유하는 이미지의 총량이지, 매달50MB씩 새로 적립되는 공간이 아니다.** 월간 전송 allowance와 저장 stock을 구분한다. 동일 기기의 로컬 cache는 서버 보유량에 다시 더하지 않는다.

MB는 십진수로 통일한다. 기존 MiB 표기와 바꿀 때 개발 기기의 한도를 몰래 낮추지 않으며, 변경 전후 byte 값을 D03에 기록한다.

## 4. 최적화·저장 사용자 경험

1. 사용자가 큰 원본을 선택해도 지원 입력 범위 안이면 곧바로 거절하지 않는다.
2. 기기에서 방향·비율을 반영해 최적화한다. 원본 파일을 덮어쓰지 않는다.
3. 크기·해상도·지원형식에 맞는 사본을 만든다. WebP 미지원 브라우저는 출력 MIME을 실제 확인하고 JPEG 등 승인된 fallback을 사용한다.
4. 서버가 인증·소유자·quota·실제 파일·픽셀·형식·크기를 다시 검증하고 정규화한 사본과 manifest를 확정한다.
5. 다른 기기에서는 이 **서버 확정 버전**을 읽는다. 각 기기가 제각기 압축한 결과를 같은 hash로 취급하지 않는다.
6. 성공한 사본이 확인되기 전 이전 사본이나 원본을 지우지 않는다.

본문 안내 예시:
- 선택 시: `기록용으로 최적화한 사본을 비공개로 연동합니다. 원본은 변경하지 않습니다.`
- 로컬만 저장: `이 기기에 저장됨 · 이미지 연동 대기`
- 원격 확정: `이미지와 기록 연동 완료`
- 일부 실패: `감상은 연동됐지만 이미지 전송이 남아 있어요. 다시 시도할 수 있습니다.`
- 다른 기기 파일 준비 중: `이미지를 불러오는 중` 또는 구체적인 재시도 상태. 즉시 ‘파일 손상’으로 단정하지 않음.
- 형식 미지원: 지원 형식을 설명하고 다른 파일/표지/디자인 선택 경로 제공. HEIC·GIF 등은 구현 없이 지원한다고 표시하지 않음.

## 5. 용량 계산 — 사용자에게 보이는 용량과 운영 물리량을 구분

### 사용자 사용량

`사용량 = 소유자의 관리 대상 개인 이미지별 기준 큰 사본 bytes + 썸네일 bytes의 합계`

새 이미지는 비공개 최적화 사본이 기준이다. 기존 공개 전용 파일만 있는 이미지에는 실제 보유 bytes를 한 번 계수하는 legacy 기준을 둔다. 나중에 비공개 사본을 연결했을 때 동일 자산·버전의 관계를 검증해 기준을 전환하며, 두 기준을 동시에 차감하지 않는다. 기존 파일을 자동무료/0bytes로 숨기거나 중복 관계를 추측하지 않는다.

`업로드 가능량 판단 = 사용량 + 진행 중 예약량 + 이번 작업에 필요한 증가량`

- 같은 asset version을 여러 Board에 참조해도 중복 차감하지 않는다.
- 별도로 만들어진 독립 카드·파일이 우연히 같다고 무조건 병합하지 않는다. 전역 사용자 간 hash 중복 제거는 첫 출시에서 만들지 않는다.
- 공용 공식 표지·시스템 디자인은 이 개인 이미지 quota에서 제외한다. 각각 메타데이터·시스템 자원 제한은 유지한다.
- 공개용으로 추가 생성한 파생본은 같은 장면을 공개했다는 이유로 사용자에게 다시 차감하지 않는 안을 권장한다. 실제 추가 bytes는 운영 전체 한도에 계산한다.
- 공개 전용으로 이미 존재하던 이미지에는 자기 파일을 증식시키지 않는 기존 계수·레거시 판별을 둔다. 기준을 바꾸려고 기존 자료를 자동 이관/삭제하지 않는다.
- UI는 `사용 중`, `전송 준비 중`, `남은 공간`을 나눈다. 실패한 예약을 영구 사용량처럼 남기지 않는다. 개수 안전상한에 먼저 도달할 수 있으면 사용량 화면에 건수·상한도 보여준다.
- 전환 시 기존 유효 사용량이50MB를 넘으면 기존 파일을 보존하고 초과 상태/새 업로드 제한을 안내한다. 기존 사용자 사용량을 갑자기0으로 초기화하거나 삭제하지 않는다.

### 운영 물리량

비공개 사본+공개 파생본+진행 파일+철회/삭제 대기+유지해야 할 이전 revision을 실제 합산한다. 백업 저장량·복구 전송은 별도 공급자 비용으로 더한다. 논리 quota가 작아도 오래된 공개본이 무한 누적되지 않게 현재 청소·수명주기와 연결한다.

파일마다 1MB라는 최대 예약값을 실제 다운로드 bytes나 고객 사용량으로 과금하지 않는다. 실제 전송 크기와 예약/반환·중단 요청은 구분한다. HTTP Range/재전송을 지원한다면 그 경로도 미터 우회를 허용하지 않는다.

## 6. 초과·삭제·공개 철회

| 상황 | 동작 |
|---|---|
| 저장 quota 도달 | 새 이미지 저장을 보류하고 현재 입력 보존. 기존 열람·정리·지원은 유지 |
| 이미지 공간 없음 | 작품/감상/공식 표지/시스템 디자인의 정상 기록은 가능 |
| 네트워크 실패 | 로컬 기록과 pending 보존, 명시 재시도. 중복 파일·중복 quota 차감 금지 |
| 공개 보드에서 카드 제거 | 해당 membership만 제거. 비공개 이미지 삭제 아님 |
| 공개 철회 | 모든 적용 공개 경로의 접근을 계약대로 중단. 자기 비공개 사본은 유지 |
| 이미지 교체 | 새 버전 검증·commit 이후 전환. 기존 공개본은 동의 없이 새 이미지로 바뀌지 않음 |
| Memory 자체 삭제 | 공개 철회/원격 tombstone/비공개 사본 정리 순서와 기존 원본 보호 적용 |
| 로그아웃/계정 전환 | 인메모리 private URL·미리보기 정리, 전송 취소·owner 재검사. 사용자 보관 로컬 기록 전체를 자동 삭제하지 않음 |
| 한도를 운영자가 낮춤 | 기존 자료를 즉시 삭제하지 않음. 추가 저장 차단·고지·정리/이의 경로 |

삭제·철회는 이미 타인이 다운로드한 사본 회수나 꺼진 기기의 즉시 삭제를 보장하지 않는다. 온라인 재검증·다음 동기화·서비스 제공 URL 차단 시점을 D05에 정확하게 정한다.

## 7. 계정 간·기기 간 약속의 범위

이번 변경의 필수는 **Memory 이미지·감상·Board**의 정상 연동이다. 작품 평점·Legacy WatchLog·Tier가 원격 동기화 대상인지 기존 구현을 확인하고 별도로 표시한다. 이번 이미지 작업을 이유로 모든 레거시 데이터를 자동 클라우드 이관하는 큰 작업을 시작하지 않는다.

PC와 휴대폰 웹의 동기화는 무료 기본값이다. 게스트에서 계정으로 자료를 옮길 때만 기존처럼 정확한 범위를 검토한다. 기존 이미지 보유 사용자에게는 선택적 `이 기기의 이미지 연동` 경로를 제공하고, 선택하지 않은 사진 전체를 업로드하지 않는다.

## 8. 미래 상품 — 방향만 보존

| 상품 방향 | 제공할 가치 | 이번에 만들지 않는 것 |
|---|---|---|
| 라이트 | 광고 도입 후 광고 제거+작은 공간 확대 | 광고 SDK, 결제, 광고 자리, 가입 유도 팝업 |
| 보관형 | 이미지를 많이 수집하는 사람을 위한 더 큰 공간·고화질/원본 선택 | 원본 업로드·구독·갱신·청구·PG·대량 복원 |

1GB·10GB·6,900원 등 과거 예시는 확정 가격표가 아니다. 현재 활성 plan은 FREE 한 개만 유지한다. 기존 일반 사용자 서버 정책에 `policy revision`과 만료 있는 예외만 연결하면 되며, 범용 entitlement/구독 엔진은 필요 없다.

유료화 전에 취소/종료/유예·내보내기·삭제 시점·세금·결제·플랫폼 규칙을 별도 승인한다. 무료 사용자 자료에 미래의 ‘90일 뒤 삭제’를 미리 실행하지 않는다. 유료라고 권리·신고 기준을 완화하지 않는다.
