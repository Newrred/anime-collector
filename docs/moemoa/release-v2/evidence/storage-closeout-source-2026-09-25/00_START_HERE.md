# MOEMOA · 무료 이미지 연동과 운영 마감 인수인계

작성일: 2026-09-25 · 문서 작성/설정 샘플. 앱 구현·테스트·운영 적용 완료 보고가 아니다.

## 한 문장 목표

**무료 이용자도 휴대폰 웹과 PC 웹에서 이미지가 포함된 기억을 이어서 사용한다. MOEMOA 추가 운영비는 월 50,000원 이내를 목표로 제한하며, 원본 무제한 백업·결제·광고를 이번 출시의 선행조건으로 만들지 않는다.**

기존 첫 정식 출시 범위인 개인 기록·계정·공개 보드·미니홈·팔로우·최소 운영은 유지한다. 비공개 연동을 위해 공개 게시를 요구하지 않는다. Android 네이티브 출시는 후속이며, 이번에는 실제 휴대폰 **브라우저**와 PC의 연결이 필수다.

## 자료를 어떻게 관리할 것인가

|---|---|---|

| `config/service-policy.candidate.json` | 용량·이미지 크기·예산·승인 근거의 기계 판독 후보값 | 아니오. 서버의 활성 revision과 비교할 설정 원본 |

이번 파일들은 전달용이다. 기존 저장소에 동등한 정책/운영 문서가 있으면 그 문서에 반영하고 링크만 연결한다. 같은 내용을 두 곳에서 계속 갱신하지 않는다. 실제 숫자는 활성 서버 정책에서 읽고, UI·서버·문서에 서로 다른 상수를 복제하지 않는다.

## 승인과 제안을 구분한다

- **사용자 확인:** 추가 운영비 월 50,000원, 도메인·홍보 광고비·다른 프로젝트로 이미 내는 Vercel 기본료 제외. MOEMOA 때문에 발생하는 초과료·세금·백업 등은 포함. 무료 웹/모바일 이미지 연동. 대량 보관 사용자 대상 미래 저장 상품, 광고 도입 이후 라이트 상품 방향.
- **이번 출시에 사용할 후보:** 무료 50MB, 큰 이미지 사본 한 장 최대 1MB, 자동 최적화. 현재 대화에서 방향에 동의했지만 최종 운영값은 품질·비용 검증과 D03에 연결한다. 여기서는 MB를 1,000,000bytes로 명시한다.
- **새 구현 제안:** 비공개 최적화 사본의 수명주기, quota 계산, 정책 revision 관리, 운영 도구. 기존 코드에 모두 있다고 주장하지 않는다.
- **미정:** 전송·전역 한도, 실제 고정비, 백업 보존/복구 목표, 국가·연령·공개 정책의 최종 승인, 유료 가격/용량. null은 무제한이 아니다.
- **이번에 하지 않음:** 플랜 구매·서버 이전·실 결제·광고 SDK·Android 배포·운영 DB 변경·Public 활성화·원본 삭제. 운영 작업은 기존 D06/권한 경계를 따른다.

## 현재 자료에 대한 주의

최신 남아 있는 `MOEMOA_Pro_LongTerm_Review_2026-09-25.zip`은 선택 소스·diff·인계 자료다. 공개 이미지 재시도·보드→작성자 연결·Web-only guard와 실제 공개 흐름은 상당 부분 검증됐다고 기록되어 있다. 그 작업을 다시 시작하지 않는다.

반면 **비공개 개인 이미지의 일반 Web 유입·서버 사본·다른 기기 열람**은 공개 사본 준비와 별개다. 현재 구현에서 충족되는 부분만 재사용하고 빠진 경로만 추가한다. 이번 문서 작성에서는 앱 전체를 실행하거나 원격 최신 코드를 조회하지 않았다.

이전 ‘무료는 공개 사본만’, ‘개인 이미지 연동은 나중’, ‘DB/Storage만 $25’, ‘6,900원/5GB’는 이번 사용자 조건과 충돌하는 범위에서 대체한다. 공개 승인·preview/consent·기존 기록 보호 원칙은 대체하지 않는다.

## 설정 파일 점검

패키지 루트에서 Node가 설치된 환경으로 실행한다. 이 도구는 로컬 파일만 읽는다.

```bash
node tools/validate_policy.mjs
node --test tools/validate_policy.test.mjs
node tools/validate_policy.mjs --release-preview
```

마지막 명령은 현재 후보의 미정값과 승인 부재 때문에 **실패하는 것이 정상**이다. `--release-preview`가 통과해도 설정의 형식·일관성만 확인한 것이며, 증빙 진위·실제 서버 적용·D06 승인·출시 완료를 증명하지 않는다. jsonschema 등 추가 패키지는 필요 없다.

`service-policy.schema.json`의 FREE-only/광고·결제 off 등은 이번 출시 범위를 고정한다. 미래 유료 상품 도입 시 명시적 결정과 schema revision을 거쳐 바꾼다. 지금 범용 과금 플랫폼을 만들지 않는다.
