## 3. 핵심 원인과 수정

0. **이미지 카드에서 제목만 클릭 가능:** MemoryCardPreview를 stretched link로 연결해 카드 이미지/여백도 같은 상세로 이동한다. 링크는 하나라 키보드 중복 정지가 없고 보드 편집 버튼은 카드 밖에서 독립적으로 동작한다. 실제 카드 영역 클릭→상세→감상 취소/복귀를 검증했다.
1. **동일한 팝업 역할을 각 화면에서 따로 구현:** 일부는 X만, 일부는 Escape만 지원했다. `useModalInteraction`으로 열기 초점, Tab/Shift+Tab 순환, 최상위 Escape, 닫은 뒤 복귀와 스크롤 잠금을 공통화했다. 중첩 팝업이 낮은 z-index 때문에 클릭되지 않는 회귀도 실제 브라우저에서 발견·수정했다.
2. **저장과 편집 상태가 명확히 분리되지 않음:** 보드의 기존 “편집 완료”가 저장 없이 접기만 했다. 취소/저장의 의미를 분리하고 원본 복원, 비동기 작업 잠금을 추가했다. 작성/감상/보드 편집의 이동 보호는 `useUnsavedNavigation`에서 관리한다.
3. **실패 안내 다음 행동이 없음:** Archive·Memory·카탈로그 재시도, OAuth 실패 복귀, 백업 파일 재선택을 보완했다.
4. **과거 기능과 현재 운영 구조가 섞임:** 옛 프로필 repo는 `updated_at`/`avatar_url`, 직접 upsert, follow/showcase 테이블을 기대한다. 현재 `user_profiles`는 `server_updated_at`, owner-only SELECT와 RPC mutation 구조다. 로그인 플래그만 켜서 옛 소셜을 제공하면 안 된다. 옛 UI는 명시적 개발 mock에서만 유지한다. 클라이언트 차단은 서버 보안 통제를 대신하지 않는다.
5. **갱신 검증 범위가 과거 3,998개 명부에 묶임:** 신규 카탈로그 검토가 추가되면 legacy 별칭 exporter가 존재하지 않는 seed를 찾다가 실패했다. 승인된 legacy 35개 대상 명부를 분리했다. 기존 대상이 실제로 없어지거나 해시가 바뀌면 계속 실패하고, 신규 카탈로그 추가는 legacy export에 섞이지 않는다.

- Docker daemon 미실행: Supabase DB 테스트/관리 SQL 실제 실행은 하지 못했다. 새 migration을 추가하거나 운영 DB에 적용하지 않았다.

## 6. 변경·복구·개인정보

변경 파일 전체 목록은 실행 증거의 `changed-files.json` 및 Git diff로 확인한다. 기존 미커밋 변경은 보존했다. 직전 `src/`, workflow, package 사본은 작업 폴더 `baseline/`에 있다. **baseline은 사용자 데이터 백업이 아니다.** 이번 source 변경만 되돌릴 때 기존 수정까지 일괄 reset하지 않는다.

운영 데이터 변경/마이그레이션/계정 생성/사용자 이미지 업로드/외부 메시지 발송/배포 없음. 새 건강 점검은 공용 카탈로그 ID·릴리스·건수·실패 코드만 출력하며 서비스 역할 키를 요구하지 않는다. 관리 SQL은 읽기 전용으로 개인 원문을 선택하지 않는다.

## 7. 완료 경계

이번 작업은 **현재 비회원·Private 기능의 조작 보완과 운영 점검 기반**이다. 실제 계정 서비스·Public 운영·자동 무검토 카탈로그 게시·상용 출시 전체를 완료한 것은 아니다. 다음 계정 공개 작업에서는 서버 한도/사용 정지/삭제, 실제 OAuth·계정 간 격리·다기기, DB 검증, 복구 훈련이 필요하다. 운영 배포 시에는 검토한 Git commit/push→Vercel Git 배포→commit SHA 대조 순서를 따른다.
