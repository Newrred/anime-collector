# 카탈로그 작품 식별·시즌 품질 정비 ExecPlan

## 1. 목적과 사용자 결과
5등분 사례에서 확인된 시즌 제목/외부 ID 혼입을 계기로 전체 현재 카탈로그를 증거 중심으로 감사하고 교정한다. 비용보다 정확성을 우선한다는 2026-09-07 사용자 요청을 따른다.

## 2. 관련 확정 결정
외부 ID·출처 보존, 작품 식별과 권리 승인의 분리, 공통 카탈로그 원칙을 유지한다. 사용자는 출시 전이며 기존 사용자 데이터 호환/이관은 고려하지 않아도 된다고 명시했다. 원본·수정 근거와 복구 가능성은 보존한다.

## 3. 현재 상태와 저장소 증거
`aliases.json`의 ANILIST:103572에 2기 제목/별칭이 혼입되어 있다. canonical 관계에는 실제 후속작 109261이 보존되지만 service projection은 legacy 한글 제목을 대표 제목으로 채택하고 READY로 표시한다. 운영 공개 검색도 이를 반환한다. 전체 오류 규모는 아직 미집계다.

## 4. 범위
현재 manifest/current/canonical/projection/aliases/출처 감사, 자동 검출과 근거 묶음, 검증된 교정안 및 재발 방지 검사. 기존 사용자 데이터 이관은 제외한다. 대규모 외부 수집·배포는 교정안과 필요 범위를 구체화한 뒤 적용 가능한 기존 승인과 공급자 정책을 확인한다.

## 5. 아키텍처·데이터 흐름
현재 pointer 기준 immutable revision 읽기 → 무결성/ID/필드/시즌/시리즈 대조 → 위험별 evidence report → 출처 확인 → 교정 기록 → 재생성·검색 검증. 추정이나 모델 응답만으로 VERIFIED 판정을 내리지 않는다.

## 6. 변경 파일 지도
`tools/catalog-lab/reports/identity-audit.mjs`, `tests/catalog-lab/identity-audit.test.mjs`, 필요 시 기존 제목 projection/quality gate. 보고서는 `docs/moemoa/reports/`와 repo 밖 별도 audit output에 보관한다.
2026-09-07 후속 실행: `config/title-identity-reviews.json`에 32개 제목 연결 검토를 기록하고, `pipeline/title-identity-review.mjs`에서 canonical/seed hash가 일치할 때만 적용한다. service projection에 교정·격리·미확인 기록을 반영하고 별도 offline staging 보고서로 전후 검색 DTO를 검증한다. canonical/raw/manifest는 증거로 유지하며 이를 수정하지 않는다. 충돌 scalar를 첫 값으로 확정하는 v2 동작도 수정하고 테스트한다.
앱의 4개 legacy alias 소비 경로는 원본 aliases.json 대신 `reviewedAliasSeed.js`를 읽는다. 생성된 최소 교정표는 원본 row가 검토 당시 값과 정확히 일치할 때만 적용하고 stale row는 검색에서 제외한다. 검색 비교·캐시 키에서 시즌 구분 기호를 보존하며 cache namespace를 갱신한다. 원본 alias roster는 수집 증거로 유지한다.

## 7. 데이터·스키마 마이그레이션
감사 단계에는 원본·pointer·운영 데이터 변경 없음. 교정 시에는 변경 전후 hash/필드별 출처/작품별 판정 기록을 남긴다. schema 변경 필요 여부는 실제 감사 결과로 결정한다.

## 8. 마일스톤
1. 정확한 대상 수와 현재 revision coverage 확정.
2. 전체 자동 감사와 시리즈별 검토 목록 생성.
3. 5등분 및 확정 충돌의 증거 검토·교정, 애매한 항목 별도 검토.
4. 정상/교정 완료/근거 부족을 구분한 재검증 결과.
5. 재발 방지와 배포용 산출물 준비, 미확인 항목 공개.

## 9. 테스트와 검증
누락·hash 위변조·ID 중복·시즌 기호 보존·관계의 ADAPTATION 제외·동일 시리즈 오탐·다국어 별칭 검사를 포함한다. 전체 감사는 데이터 누락이나 파싱 실패를 정상으로 간주하지 않는다. 결과를 표본 대조해 규칙 오탐을 확인한다.

## 10. 보안·개인정보·권리 영향
공개 카탈로그와 허용된 로컬 원본만 읽는다. 사용자 데이터는 조회하지 않는다. API key·원본 이미지 bytes·비공개 기록을 모델 입력이나 보고서에 포함하지 않는다.

## 11. 관찰 가능성·분석 이벤트
대상 수·검사 범위·규칙별 발견 수·미확인 수·입력 hash·재개 가능한 판정 상태를 기록한다. 정상 판정과 단순 무경고를 구분한다.

## 12. 롤백·복구
기존 immutable 파일과 current pointer snapshot으로 복구한다. 교정은 검토 가능한 변경 manifest로 분리한다. 자동 합치기/삭제는 수행하지 않는다.

## 13. 위험과 완화
제목 유사도는 동일 작품의 증거로 쓰지 않는다. sequel/prequel은 검토 후보이며 리메이크/분할 시즌/특별편을 구분한다. 모든 작품의 정확성을 검사 규칙만으로 보장했다고 보고하지 않는다.

## 14. 필요한 사용자 결정
정확성 우선·기존 사용자 이관 제외는 이미 확인됐다. 현재 로컬 전수 감사에는 추가 결정이 없다. 외부 모델이 필요하면 검토 대상과 근거 묶음을 먼저 구체화한다.

## 15. 진행 기록

## 16. 발견 사항과 계획 변경
리뷰 후 보완: 게시 시 현재 정책으로 제목 projection을 재계산해 저장된 제목·별칭·격리값과 대조한다. 새 source 한국어 별칭까지 관계/시즌 검사를 확장한다. 앱 검색은 기호를 포함한 엄격 비교와 사용자가 기호를 생략한 경우의 느슨한 비교를 분리한다. 명시적으로 입력된 시즌 기호는 느슨한 검색으로 제거하지 않는다. 세 재현 사례를 회귀 검사에 추가한다.
초기 단일 제목 오류뿐 아니라 검수 완료 판정에 시즌 혼입 검사가 없는 점을 감사한다.
바쿠만 2기(10030)의 원제 Bakuman. 2가 season:2로 해석되지 않아 관계 제목 검사에 걸리는 오탐을 확인했다. 검출 수를 확정 오류 수로 사용하지 않는다. 필드 충돌 219개는 공식 URL 161, 화수 52, 시작일 7건으로 나뉘며 한 작품에서 중복될 수 있다.

현재는 제목 연결 우선 교정과 재발 방지의 로컬 구현 완료다. 전수 내용 검토, 누락 복원, 한국어 명칭 7개, 충돌 필드 검토와 운영 배포는 남아 있다. source 접근 실패를 정상·빈 작품 데이터로 대체하지 않는다.

### 후속 검토 수정 완료
세 재현 문제를 수정했다. 카탈로그 241 통과/2 skip, 앱 227 통과, 웹 15페이지 빌드 및 React Doctor 기존 진단 유지. 4,224개 staging 재검사에서 별칭까지 확대한 gate가 추가 4개를 검토 대상으로 보류했다. 기존 보고서의 unresolvedIdentity 0은 이전 규칙 결과이며 현재 값은 4다. 원본/운영 변경 없음. 상세: [후속 개선 보고서](../reports/2026-09-07-catalog-identity-review-fixes.md).

### 추가 4개 제목 연결 검토 계획
공식 작품 소개와 원본 canonical/관련 작품을 대조한다. 정상 시즌/세대/미니 애니 번호는 원본 hash에 묶인 검토 예외로 유지하고, 다른 작품과 정확히 겹치는 포괄 별칭은 격리한다. 전역 검사 완화 없이 교정표와 앱 별칭을 갱신하고 회귀 테스트 및 4,224개 staging 재검사를 수행한다. 운영/원본 변경은 없다.

추가 4개 검토 완료: 정상 번호 별칭 3건 유지, 퀸즈 블레이드의 모호한 별칭 1개 격리. 전체 검토 기록 36개/앱 AniList 별칭 35개. 4,224개 재검사에서 현재 제목 감지 미해결 0, 관련 ID 미보유 후보 40, 한국어 대기 7이다. 운영/원본 미변경. 상세: [4개 검토 보고서](../reports/2026-09-07-catalog-four-title-reviews.md).

### 운영 제목 교정 배포 완료
사용자 승인 후 35개 제목·별칭을 운영 DB의 새 릴리스로 반영하고 웹을 배포했다. 실제 검색 검증 완료. 전수 데이터 검증이나 미수록 작품 복원 완료는 아니다. [운영 보고서](../reports/2026-09-07-catalog-correction-production.md).

### 5등분 2기 누락 복원 실행
사용자 후속 진행 요청으로 AniList 109261 한 작품부터 복원한다. 공식 2기 작품 정보와 독립 ID를 대조하고 승인된 API 접근 상태를 한 번 확인한다. 실패 시 반복 요청하지 않고 이용 가능한 공개 증거와 기존 수집 경로를 확인한다. 별도 ID/출처/표지 검증을 통과해야 게시하며 1기 표지를 재사용하지 않는다.

2기 공개 페이지는 접근 가능하므로 REVIEWED_PUBLIC_RENDERED_PAGE 출처로 보존한다. 정상 API 응답으로 표기하지 않는다. 인물/성우는 NOT_FETCHED로 보존한다. 기존 reviewed_increment 한국어 제목 근거와 원본 파이프라인으로 신규 UUID를 만들고, 승인된 AniList CDN의 전용 표지를 검증한다. 사용자 후속 진행 요청에 따라 운영 목록을 보존한 새 릴리스에 1개만 추가하고 기존 activation/rollback 절차로 반영한다. 웹 코드 변경은 필요하지 않다.

### 5등분 2기 복원 완료
AniList 공개 페이지 검토 + 한국어 출처 대조로 109261을 독립 UUID로 생성했다. 전용 표지 검증 및 244 테스트 통과/2 skip. 운영 3,999개 새 release 활성화 및 실제 웹 1기·2기 분리 검색→상세 확인. 원본 4,224개 lab은 유지하고 신규 canonical은 별도 보충 workspace에 보존하므로 다음 전체 재생성에서 합쳐야 한다. [상세 및 복구](../reports/2026-09-07-quintuplets-season2-restoration.md).
