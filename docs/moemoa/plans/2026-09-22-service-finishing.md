# 기존 서비스 UX·운영 마무리 ExecPlan

## 1. 목적과 사용자 결과
새 제품 기능 개발을 멈추고 기존 화면의 예상 가능한 조작·복귀·오류 회복과 최소 운영 통제를 보완한다.
## 2. 관련 확정 결정
01 확정 결정, 02 사용자 흐름, 07 운영 기준, Git 기반 운영 배포 결정 준수. 기존 갤러리 유지, Private 기본값, Public 출시 게이트 유지.
## 3. 현재 상태와 저장소 증거
15개 Astro 경로. MemoryConflictDialog/ConflictResolveModal은 키보드 모달 동작이 부족하고 GlobalQuickActionSheet도 초점 관리가 없다. MemoryBoardView.run/create는 실행 중 잠금이 없다. .github/workflows/astro.yml은 master push에 Pages를 배포한다. 사용자 metadata는 RLS+RPC, 기존 공개 프로필/팔로우는 별도 repository 경로다.
## 4. 범위
### 포함
모든 경로와 주요 조작의 코드/브라우저 점검표, 모달·취소·오류·중복 실행 보완, 기존 소셜 노출/관리 권한 감사, 호출량 통제 검토, 카탈로그 갱신 검증 자동화와 운영 절차.
### 제외
신규 탐색/추천/소셜 기능, Public 활성화, 운영 DB 변경, 계정·개인 데이터 조작, 자동 운영 배포.
## 5. 아키텍처·데이터 흐름
기존 UI→application→local repository→선택적 Supabase sync 경계 유지. 관리 권한은 서버/운영 CLI 경계에 둔다. 카탈로그 수집→검증→후보→승인된 릴리스 흐름을 유지한다.
## 6. 변경 파일 지도
src/hooks 모달 공통 동작, 기존 modal/sheet와 MemoryBoardView, scripts 운영 점검, .github/workflows 검증, tests 및 docs/moemoa/reports. 추가 변경은 실제 발견 근거와 함께 기록한다.
## 7. 데이터·스키마 마이그레이션
우선 없음. 필요 시 버전 관리되는 별도 SQL과 검증 경로를 준비하고 운영 적용은 분리한다.

## 9. 테스트와 검증
격리 Playwright 프로필, 기존 주요 사용자 흐름과 닫기/초점/취소/중복 조작 회귀. npm run test:unit, npm run build, catalog:test, 운영 점검. 실제 계정·Android·배포 상태는 실행 증거 없으면 미검증으로 표시한다.
## 10. 보안·개인정보·권리 영향
서비스 역할 키를 브라우저에 전달하지 않는다. 사용자 원문/이미지는 보고·로그에서 제외. 테스트는 생성한 가상 자료만 사용한다.
## 11. 관찰 가능성·분석 이벤트
자동 점검에는 코드/릴리스 ID·건수·실패 코드만 기록한다. 신규 개인 분석 수집 없음.
## 12. 롤백·복구
기존 미커밋 변경을 보존하고 이번 작업 직전 파일 사본을 workspace 바깥 작업 폴더에 보관. 배포/DB 변경이 없으면 운영 롤백 불필요.
## 13. 위험과 완화
모달 중첩/빠른 연속 클릭/저장 중 닫기를 회귀 검사한다. 클라이언트 제한을 서버 보안 한도로 오인하지 않는다. 카탈로그 보충 배치 누락을 검사한다.
## 14. 필요한 사용자 결정
기존 기능 수정은 현재 요청으로 승인됨. Public 활성화·실계정 작업·운영 배포는 이번 구현에 포함하지 않는다.
## 15. 진행 기록
2026-09-22: 저장소 지침·운영 기준·경로·모달·보드·RPC·배포 workflow 확인. 변경 전 계획 작성.
## 16. 발견 사항과 계획 변경
기존 공개 프로필과 Private Memory Public gate를 구분했다. 모달 적층 클릭 실패, 카드 이미지 비클릭, 신규 카탈로그 review와 legacy alias exporter 범위 충돌을 추가로 발견·수정했다. 서버 계정 한도/삭제 및 운영 권한 실검증은 계정 공개 전 미완료 게이트로 분리했다. Docker daemon이 없어 DB 테스트/새 migration은 수행하지 않았다.
