MOEMOA 운영 방향·정책·관리자 검토 패키지
검토 기준일: 2026-10-18

1. 이 패키지의 용도

앞으로의 운영 방향과 일정, 이용자에게 공개할 정책 문안, 운영자가 처리할 사건과 관리자 보고를 함께 검토하기 위한 패키지입니다. 실제 운영에 적용할 범위와 순서를 결정할 수 있도록 분석, KO/EN 문안, 관리자 시안, 연결 명세, 순수 로컬 보고 생성기, 작은 표시 수정 패치를 모았습니다.

원본 검토 저장소와 production 사이트·DB·Storage·계정·예약 작업은 수정하지 않았습니다. 정책 문서를 게시하거나 실제 이메일을 보내지 않았습니다. 이 패키지를 열거나 로컬 보고 예제를 실행하는 것만으로 운영 설정이 바뀌지 않습니다.

2. 완성본 구성

- 운영·전략 보고서 DOCX: 서비스의 운영 방향, 시장·대체 서비스, 우선순위, 일정과 판단 근거.
- 법률·정책 문안 DOCX: 한국어 전체 5종과 긴급·권리 안내의 영문, 기한·공급자·적용 조건. 약관·개인정보·공개 정책의 전체 영문은 public-documents/의 별도 HTML에 포함합니다.
- 대화에 표시한 관리자 시안: 오늘 할 일, 사건 처리, 서비스 상태, 보고·전송, 감사 흐름을 합성 사례로 검토하는 화면. 대화 내 시안은 이 압축 파일과 별도로 제공하며, 관련 설계와 합성 사례는 관리자 연결 명세에 포함합니다.
- 관리자 연결 명세 HTML: 현재 구현, 추가할 API/RPC·사건/기한·outbox, 역할 구분, 재시도·감사·해결 조건, 개발 일정.
- 법률 및 시장 근거 HTML: 본문 판단의 자세한 출처와 남은 확인 사항을 읽는 자료.
- policy-decisions.json: 정책 원고의 모든 {{...}} 토큰을 추출한 미확정 값 registry. 확인된 문의 이메일은 verified_source에 별도로 기록.
- code/: 외부 연결 없는 관리자 보고 생성기와 입력 예시·기존 로컬 검사. 자세한 사용법은 code/README.txt.
- email-samples/: 일일·긴급·주간 보고의 HTML와 일반 텍스트 합성 예시.
- patches/: 관리자 사용량 표의 한도 적용 범위 표시를 고치는 독립 patch와 README.txt.

대화의 관리자 시안과 email-samples는 실제 신고·이용자·장애·사용량을 보여주는 화면이 아닙니다. 합성 수치와 사례를 현재 실적으로 해석하지 마세요.

3. 읽는 순서

먼저 운영·전략 보고서를 읽고 서비스의 우선순위와 8주간 검증 방향을 정합니다. 이어 관리자 HTML 시안에서 실제로 하루에 어떤 일을 하게 될지 확인하고, 연결 명세에서 기존 기능과 추가 구현을 구분합니다.

그다음 정책 DOCX와 법률 근거를 policy-decisions.json 옆에 놓고 대조합니다. 각 변수에 필요한 신원·계약·국가·보관·시행일·URL·작동 경로를 확인합니다. 시장 근거는 모집 대상과 차별화 판단을 더 자세히 검토할 때 사용합니다.

마지막으로 email-samples의 정보량을 확인하고, 개발 담당자는 code/README.txt와 patches/README.txt를 읽습니다. 정책 문안이 있다는 사실과 그 약속을 실행하는 기능이 연결됐다는 사실을 구분해야 합니다.

4. 정책 문안의 상태와 미확정 값

문안은 KO/EN 대조 초안이며 최종 대조가 필요합니다. 실제 법적 사실, 운영자 표시, 공급자 상품·계약 적용, 처리 국가, 연락처, 보관·삭제 동작, 신고·권리 요청의 실제 작동 경로를 확정한 뒤 게시해야 합니다. 법률 적용성 판단과 운영자 선택을 초안이 대신 확정하지 않습니다.

policy-decisions.json의 모든 정책 변수 값은 null이며 status는 operator_or_contract_confirmation_required입니다. 설명문에서 사용한 {{변수}} 문법 예시도 누락 없이 기록하되 illustrative_syntax로 구분했습니다. JSON은 운영 설정 파일이나 자동 치환 프로그램이 아닙니다.

검토일 2026-10-18을 실제 효력 발생일로 쓰지 않습니다. 운영자의 실제 성명·주소·전화·사업자등록·지정 대리인 신원을 추정해서 채우지 않습니다. 활동명이나 문의 이메일이 확인됐다는 이유로 법적 신원과 등록이 확인됐다고 표시하지 않습니다.

godburgundy@gmail.com은 첨부된 현행 문서에서 확인한 문의 이메일 문자열로 별도 verified_source에만 기록했습니다. 현재 수신·응답, 상시 긴급 대응, Gmail API/SMTP 발신 권한, 지정 대리인 등록 또는 전용 폼의 구현을 확인했다는 뜻은 아닙니다.

기존 약관·개인정보 문서 URL과 과거 수락 기록을 새 문안으로 덮어쓰지 않습니다. 최종 게시일, 새 문서 버전·해시·공개 revision, KO/EN 링크와 가입 수락 연결을 하나의 검토된 전환 계획으로 적용해야 합니다.

5. 관리자와 보고 생성기가 실제로 하는 일

관리자는 시안과 연결 명세입니다. 실제 /admin/과 /moderation/의 기능을 바탕으로 추가할 운영 흐름을 제안하며, 이 HTML 자체가 새 사건 DB나 실제 운영 버튼에 연결된 것은 아닙니다. 시뮬레이션의 가림·재시도·해결은 실제 자료를 변경하지 않습니다.

service_admin과 content_moderator는 실제 서버 권한에서 구분해야 합니다. 서비스 집계 권한을 개인 기록·사진 전체 열람 권한으로 확대하지 않습니다. 공개 대상 하나의 HIDE, 알려진 동일 사본의 처리, 물리 삭제, 신청자 안내, 법률상 사건 완료는 서로 다른 결과입니다. 원접수와 유효 요청 수신 시각을 보존하고 내부 목표와 법정 기한을 나눕니다.

code/의 보고 생성기는 Node.js 기본 모듈로 입력 검증과 제목·텍스트·HTML·중복 방지 키 생성만 수행합니다. 네트워크 요청, DB 접속, 실제 발신, 예약 작업 등록은 없습니다. 예제를 실행하면 로컬 email-samples 파일을 생성합니다. 테스트와 사용법은 code/README.txt에 있습니다.

실제 보고 연결에는 안전한 집계 projection, outbox·lease·멱등성·UNKNOWN/DEAD 처리, 인증된 발신 계정, 고정 관리자 수신자, 운영 작업 heartbeat와 독립 누락 감시가 추가로 필요합니다. 로컬 테스트 통과는 실제 수신이나 production 연결 검증이 아닙니다.

6. 독립 표시 수정 패치

patches/admin_quota_scope_labels.patch는 현재 AdminDashboard에서 전역 IMAGE_DELIVERY 및 IMAGE_DELIVERY_BYTES 한도를 계정별 한도처럼 설명하는 오류를 고치는 후보입니다. 계정별/서비스 전체 범위 열과 문구를 수정하고, 기존 영문 UI 검사의 열 이름 기대값 한 곳을 맞춥니다. 한도 값·서버 호출·권한·삭제·배포 설정을 바꾸지 않습니다.

원본 저장소에 적용하지 않았고 git apply --check만 통과했습니다. 이 결과는 diff의 적용 가능성을 확인한 것입니다. 수정 후 브라우저·build·production 검사를 통과했다는 뜻은 아닙니다. 적용 담당자가 실제 개발 checkout에 반영한 뒤 기존 격리 mock의 관리자 한글·영문·좁은 화면 사례를 확인하면 됩니다. 상세 근거와 최소 명령은 patches/README.txt에 있습니다.

7. 다음 적용 순서

1) 운영 방향과 초기 모집 범위, 공개 기능의 지원 여력, 우선순위와 담당 확인 시간을 정합니다. 모집 대상을 정하는 결정과 기존 가입 국가·연령 정책 변경을 구분합니다.
2) policy-decisions.json의 변수와 법적 적용 조건을 실제 사실·계약·작동 경로에 맞춰 채웁니다. 문서의 KO/EN 내용과 기능의 약속을 대조하고 적용하지 않는 선택 조항을 정리합니다.
3) 독립 개발 checkout에서 작은 라벨 patch를 적용·확인하고, 기존 사건·검토·알림 RPC에 최소 운영 메타데이터와 기한 흐름을 연결합니다.
4) 비회원 요청 접수, 현재 revision에 묶인 개별 조치, 알려진 동일 사본의 범위 판단, 신청자 안내와 해결 조건을 격리·합성 데이터로 검증합니다. 알려진 비공개 연결의 법적 검토가 미해결인데 전체 완료로 표시하지 않습니다.
5) 로컬 보고 생성기에 안전한 집계를 연결하고 outbox·재시도·불명 상태·heartbeat를 구현합니다. 원문·이미지·비밀키를 관리자 메일에 넣지 않습니다.
6) 정확한 commit·migration·대상 환경·복귀 계획, 실제 발신 계정·고정 수신자·시험 메일 한 통, cron 정의와 누락 검사 범위를 검토한 뒤 실제 연결을 승인합니다.
7) 최종 문서 URL·버전·해시·revision을 실제 가입/공개 흐름에 연결하고, 비회원·현재 이용자·철회·신고·한도·통지 경로를 필요한 범위에서 확인합니다. 신규 정책과 기능을 그 확인된 시점부터 적용합니다.

새 보고 연결을 중단하더라도 접수·기한·감사 기록과 수동 운영은 남겨야 합니다. 배포 rollback이 별도의 권리 차단을 해제하거나 작성자가 철회한 자료를 다시 공개하게 해서는 안 됩니다.

8. 인증정보와 자료 취급

이 검토 패키지에 실제 credentials, 로그인 토큰, service key, 메일 발신 비밀, 복구키를 넣지 않았습니다. 로컬 예제는 이런 값이 필요하지 않습니다. 외부 연결 시에는 승인된 서버/계정의 비밀 관리 경로를 사용하고 문서·프런트엔드·메일 본문·로그에 값을 붙여 넣지 않습니다.

문의 원문·개인 감상·사용자 사진을 실제 데이터 예제로 채우지 마세요. 새 자동 삭제나 보존 만료 작업은 이 패키지를 받는 것만으로 승인되거나 활성화되지 않습니다.
