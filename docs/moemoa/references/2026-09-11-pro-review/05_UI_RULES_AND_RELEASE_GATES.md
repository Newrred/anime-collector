# 적용 가능한 UI 기준과 출시 게이트

아래 수치는 리뉴얼을 강제하는 외부 표준 주장이 아니라 **현재 디자인 토큰 위에서 적용할 리뷰 제안값**이다. 유지하기로 한 표지 Gallery를 일반 카드 UI로 다시 만들지 않는다.

## 1. 화면 역할과 1순위 행동

| 화면 | 사용자 질문 | 1순위 행동 | 보조 행동/뒤로 |
|---|---|---|---|
| Home | 최근 무엇을 남겼고 다음에 뭘 할까? | 기억 남기기 또는 최근 기억 열기 | 작품 검색/최근작품; 통계는아래 |
| Titles Poster | 어떤 작품이 내 기록에 있지? | 작품 열기 | 장르/상태/열수/정렬 유지 |
| Titles Memory | 이 작품에 무엇을 남겼지? | Memory preview 또는 Title Hub 열기 | 보기전환/필터 |
| Title Hub | 이 작품의 상태와 기억은? | 같은작품에 기억 남기기 | 작품저장/상태편집,이전목록복귀 |
| Archive | 저장한 모든 기억 중 어느 것을 찾을까? | Memory 열기/검색 | 생성/선택후Board담기 |
| Composer | 이 순간을 어떻게 남길까? | 저장 | 작품/Visual변경,취소;가용옵션만 |
| Memory Detail | 그때 무엇을 느꼈지? | 읽기/이미지보기 | 작품보기/보드담기/수정;삭제는더보기 |
| Board | 같은주제의기억을다시보자 | Memory Gallery 열람 | 편집/연결/순서변경 |
| Data/Account | 무엇이 어디에 저장되고 복구되나? | 실제상태확인/지원범위백업 | 계정/승격/고급진단 |

Home/Archive를 새로 병합하지 않는다. 자료에있는4개주메뉴는현재로유지하고역할을분명히한다. 모바일bottomnav는추가사용성근거후결정하며기본필수아님.

## 2. 이미지·카드·밀도

- **Poster View:** 기존2:3,좁은gallery gap(현재2px),태그/열설정 유지. 정상표지아래메타를일괄강제하지않는다. 접근가능이름은작품명포함.
- **표지없음/PrivateTitle:** 이경우만빈타일에작품명최대2줄과구분기호. 여러개가전부‘개인’으로만보이지않게한다.
- **Memory View:** cover는식별영역,preview는실제남긴Visual. 1장=1열,2장=2열,3장이상=최대3개+남은수. 참고값:preview한칸최소96~120px를목표로삼되화면너비에맞춰열을줄인다.
- **시스템 디자인 thumbnail:** artwork형태/색/짧은cue 중심. 긴footer·‘비공개메모리’장문을작게축소해낱글자세로열로만들지않는다.
- **Archive/Board:** 공용4:5 frame과Memoryrenderer 유지. 원본비율은detail에서보존하고포스터는contain 등기존타입별규칙재사용.
- **Board:** 목록과상세에이미지필수. 순서화/삭제control은이미지를가리지않고편집시에만노출. 기존읽기/편집상태보존.
- **성능:** 목록은필요한2~3preview만지연로딩. 전체작품×전체이미지bytes를동시에읽는구조는프로파일링후개선한다. 현재자료만으로성능문제가이미실발생했다단정하지않는다.

## 3. 간격·타이포·색상

- 앱기본space토큰은4/8/12/16/24/32를재사용. Mobilepagepadding12~16px,desktop주요section사이24~32px를시작점으로삼는다.
- 표지Gallery간격은위규칙예외로기존2px유지. 이예외를일반form/Memory간격에전파하지않는다.
- 본문14~16px,핵심감상15~16px,보조12~13px,section20~24px,페이지제목28~32px를시작점으로기존토큰조정. 표지내원본텍스트는이규칙과별개다.
- 제목/짧은감상2줄clamp;전체텍스트는detail에서읽기. 좁은preview에서단어/한글이한글자씩세로로나오면내용축약/레이아웃변경.
- 현재MOEMOA브랜드포인트색유지. primary만포인트강조,보조는subtle,삭제는위험영역. 모든박스를테두리/같은강도로둘러싸지않는다.
- 색만으로saved/sync/error를구분하지않는다. actualtext/icon을함께쓴다. 대비수치합격은측정전선언하지않는다.

## 4. 컨트롤과 접근성

- 프로젝트의모바일주요터치영역44px기준유지. 표지자체는타일전체link,이미지preview는독립link.
- 링크안에링크/버튼을중첩하지않는다. 작품명→Hub,preview→Memory가각각키보드로접근가능해야한다.
- 폼라벨은고정된필드명. 도움말/글자수/오류는연결된보조설명으로분리한다.
- 페이지당main하나,예측가능한heading. 현재Board의중첩main수정.
- 저장중은중복실행불가,완료는status,즉시오류는alert. 자동초점이사용자입력을방해하지않게.
- modal은닫기/Escape/초점복귀;긴모바일form은keyboard+safearea에서마지막버튼노출.
- `320×720,390×844,1440×1000`과KO/EN,light/dark,0/1/많은기록을확인. 원본91장은주로390/1440이며320성공으로대체하지않는다.

## 5. 용어/상태 계약

| 데이터/행동 | 사용자 표현 | 피할 표현 |
|---|---|---|
| Save Title | 작품 저장 | 카드 추가와혼용 |
| Add Memory | 기억 남기기 | 저장위치부터고르게하기 |
| Poster/Memory | 표지 보기 / 기억 함께 보기 | Library/Archive가새로생기는듯한이름 |
| PrivateTitle | 개인 작품명 | 작품 또는 카드 제목처럼대상혼용 |
| WatchLog | 시청 기록 | 이미지 Memory와같은‘기억’으로표시 |
| Local data | 이 기기에 저장 | 자동백업됨 |

## 6. 날짜·변경·삭제

`watchedAt/createdAt/updatedAt`은서로다르다. 현재updatedAt정렬을쓴다면사용자에게수정일이라표현하거나원하는정렬필드를새로정의한다. 값없는감상일을작성일로무언대체하지않는다. UTC/기기로컬표시일관성과자정전후를테스트한다.

- 작품저장해제:어떤tracking항목이사라지는지정확히고지;Memory/Board유지.
- Board제거:membership만제거,원본Memory유지.
- Board삭제:Board와membership,원본Memory유지.
- Memory삭제:해당카드와참조관계/개인파일관리;공용catalogcover는삭제금지.
- 가져오기교체:범위preview/사전backup/사용자확인후실행. 설정을바꾼다고로컬데이터초기화하지않는다.

## 7. 출시 게이트 — 서로 대체하지 않음

### A. 소규모 Web 사용성 테스트: 지금 시작 가능

샘플/폐기해도되는테스트기록,기능한계명시,다른계정/운영데이터와분리된환경이라면현재구조로도첫흐름을시험할수있다. 전체제품개편이나Public완료를기다릴필요없다. 참가자에게실제장기개인기억을안전하게백업해준다고약속하지않는다.

### B. 실제 개인 기록을 받는 Web local beta

출시필수: R02/R03수정,같은개인작품후속기록,자체ID기본tracking또는명시적범위제한,정확한저장/백업안내와지원범위의복구증거,실패/중복/삭제회귀,핵심Mobile읽기품질. 현재노출하는Board는기본이미지열람을갖추거나미완성기능임을범위에명시한다.

P1전체완료가자동필수는아니다. 고급회고/프로필/Tier고도화/이미지클라우드/소셜/Public은빼도된다. 다만사용자에게보여주는기능의안전성·약속은충족해야한다.

### C. 계정/동기화 사용 공개

별도실계정확인:Guest승격preview/취소/실패원본보존,같은계정다기기,다른계정전환,삭제전파,충돌·권한만료·재시도,메타와파일범위표시. 모의단위통과만으로계정beta완료라하지않는다. localbeta에실계정연결을노출한다면해당gate가필요하다.

### D. Android beta

실제기기PhotoPicker/ShareTarget,권한거부/취소,EXIF/큰이미지/저장부족,앱재시작/processdeath,keyboard/safearea/back,파일교체/삭제/복구,OAuth복귀. Webscreenshot/모의테스트/APK존재는이를대체하지않는다.

### E. Public

PublicCard/Board계약,게시동의,표지외사용자이미지권리,신고/차단/삭제/운영체계,비공개정보노출방지등을별도로승인한다. 공식표지Visual사용승인은공개서비스gate의대체물이아니다. Private beta에서는비활성유지가능하다.

## 8. 사용자 검토 제안

5명내외의탐색적테스트를출발점으로권장한다. 표본수가작으므로통계적시장검증이라고표현하지않는다.

과업: 설명없이작품찾기→공식표지/시스템디자인으로첫기억→같은작품에두번째기억→하나의기억다시찾기→Board에담기→현재저장/백업범위를자기말로설명.

관찰: 첫클릭,갈림길에서멈춘지점,첫저장시간,잘못선택한작품/개인제목수,두번째카드앨범연속성,목록왕복후재탐색,저장/공개오해. 첫저장2분·10초내primary식별은기존방향과맞춘목표값이지이번에달성한수치가아니다.

## 9. 아직 결정할 것

1. **Web 처음 흐름:** title-first 제안 채택여부. Android공유의image-first는유지.
2. **작품저장해제:** watchstate/rating/log를남기는지지우는지;실제범위를명시.
3. **Web beta 백업 범위:** 신규metadata복구부터할지native파일archive까지인지.
4. **PrivateTitle tracking:** 개인작품은Memory묶음만인지작품저장/시청기록까지지원할지. 두번째Memory추가와별개.
5. **날짜 기본 의미:** 감상일/작성일/수정일중어느것을목록에노출할지.
6. **계정/Profile/Tier 노출:** 검증전숨김/실험기능/부가메뉴중선택. 새Public을자동활성하지않음.

확인된버그수정은최소변경으로진행할수있지만,위제품행동변경은제안과승인을구분해기록한다.
